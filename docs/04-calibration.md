## ลำดับการ calibrate ที่แนะนำ

การ calibrate มีลำดับพึ่งพากัน — ทำผิดลำดับจะต้องทำซ้ำ

```
วันที่ 0    ประกอบระบบให้เสร็จสมบูรณ์ในตำแหน่งจริง (ในกล่อง/บนโต๊ะที่จะใช้จริง)
              ↓
วันที่ 0    เปิด MQ-2 burn-in ต่อเนื่อง (ถ้าใช้)                    ← 24–48 ชม.
              ↓
วันที่ 0    เปิดระบบทั้งหมด รอความร้อนเข้าที่                       ← ≥ 30 นาที
              ↓
วันที่ 0    ① SCD40 temperature offset                             ← ต้องทำก่อนตัวอื่น
              ↓                                                       เพราะ RH ขึ้นกับ T
              ② SCD40 ตั้งความสูง/ความดัน
              ↓
วันที่ 0    ③ ไมโครโฟน dB offset
              ④ BH1750 transmission factor
              ↓
วันที่ 0–1  ⑤ SGP30 baseline สร้างเองอัตโนมัติ                    ← 12 ชม.
              (ต้องรอ ① เสร็จก่อน เพราะใช้ RH จาก SCD40 ชดเชย)
              ↓
วันที่ 1–2  ⑥ MQ-2 หา R0 (ถ้าใช้)                                  ← หลัง burn-in
              ↓
วันที่ 5+   ⑦ SCD40 FRC                                            ← datasheet บอกให้รอ ≥5 วัน
                                                                      หลังประกอบเสร็จ
```

## SCD40 — temperature offset

**นี่คือขั้นตอนที่สำคัญที่สุดในเอกสารทั้งฉบับ** เพราะมันกระทบทั้งอุณหภูมิ ความชื้น
และความแม่นยำที่ datasheet โฆษณาไว้ทั้งหมด

### ทำไมจำเป็น

SCD40 วัดอุณหภูมิที่ตัวชิปเอง ซึ่งร้อนกว่าอากาศจริงเพราะ:

1. ความร้อนที่ตัวเซนเซอร์สร้างเอง
2. **ความร้อนจาก SoC ของ Pi 5** ที่แผ่มา (Pi 5 ร้อนกว่า Arduino UNO Q มาก)

ค่าเริ่มต้นจากโรงงานคือ **4 °C** ซึ่งเหมาะกับการติดตั้งบน PCB ขนาดเล็ก ไม่ใช่กรณีนี้

### สิ่งที่ต้องเตรียม

- เทอร์โมมิเตอร์อ้างอิงที่แม่นยำ (ยิ่งแม่นยิ่งดี — ควรมีความละเอียด 0.1 °C)
- เวลา ≥ 1 ชั่วโมง

### ขั้นตอน

```
1. ประกอบระบบให้เสร็จสมบูรณ์ในกล่อง/ตำแหน่งจริง
   ⚠️ ห้าม calibrate ตอนวางเปล่า ๆ บนโต๊ะแล้วค่อยเอาไปใส่กล่อง — ค่าจะใช้ไม่ได้

2. เปิดระบบทิ้งไว้ ≥ 30 นาที ให้อุณหภูมิเข้าสู่สมดุล
   (30 นาที ไม่ใช่ 5 นาที — Pi 5 ใช้เวลาถึงจุดสมดุลนาน)

3. วางเทอร์โมมิเตอร์อ้างอิงข้างตัวเซนเซอร์ ห่างไม่เกิน 5 cm
   รออีก 10 นาทีให้เทอร์โมมิเตอร์เข้าที่

4. อ่านค่าพร้อมกัน:
      T_scd40    = อุณหภูมิที่ SCD40 รายงาน
      T_อ้างอิง   = อุณหภูมิจากเทอร์โมมิเตอร์
      offset_เดิม = อ่านด้วยคำสั่ง get_temperature_offset (0x2318)

5. คำนวณ:
      offset_ใหม่ = offset_เดิม + (T_scd40 − T_อ้างอิง)

6. เขียนค่า:
      stop_periodic_measurement()      ← ต้องหยุดก่อน
      รอ 500 ms
      set_temperature_offset(offset_ใหม่)
      persist_settings()               ← ⚠️ เรียกครั้งเดียวเท่านั้น (EEPROM มีจำนวนรอบจำกัด)
      start_periodic_measurement()

7. รออีก 30 นาที แล้วตรวจซ้ำ — ควรต่างจากค่าอ้างอิงไม่เกิน ±0.5 °C
```

### ตัวอย่าง

```
offset ปัจจุบัน  = 4.0 °C
SCD40 อ่านได้    = 32.5 °C
เทอร์โมมิเตอร์   = 28.0 °C

offset ใหม่ = 4.0 + (32.5 − 28.0) = 8.5 °C
```

ค่าที่พบบ่อยเมื่อวางใกล้ Pi 5: **6–10 °C**

### 💡 วิธีที่ดีกว่าการตั้ง offset สูง ๆ

**ย้ายเซนเซอร์ให้ห่างจากแหล่งความร้อน** ด้วยสาย I2C ยาว 10–20 cm ออกไปนอกกล่อง

| | offset ต่ำ (1–3 °C) | offset สูง (8–10 °C) |
|---|---|---|
| ความแม่นยำเมื่อโหลด CPU เปลี่ยน | ✅ ยังแม่น | ❌ เพี้ยน — เพราะความร้อนเปลี่ยนแต่ offset คงที่ |
| ความแม่นยำเมื่ออุณหภูมิห้องเปลี่ยน | ✅ ยังแม่น | ⚠️ เริ่มเพี้ยน |

การชดเชยด้วยตัวเลขคงที่จะแม่นเฉพาะเมื่อความร้อนที่แผ่มาคงที่ ซึ่งไม่จริงเมื่อ CPU ทำงานหนักบ้างเบาบ้าง
**การย้ายเซนเซอร์ออกห่างจึงเป็นวิธีแก้ที่ต้นเหตุ**

## SCD40 — CO₂

### ASC เทียบกับ FRC

| | **ASC** | **FRC** |
|---|---|---|
| หลักการ | สมมติว่าค่าต่ำสุดในรอบ ~7 วันคือ 400 ppm | บอกเซนเซอร์ตรง ๆ ว่าตอนนี้กี่ ppm |
| เงื่อนไข | ต้องสัมผัสอากาศ ~400 ppm **สัปดาห์ละครั้ง** | ต้องพาไปที่อากาศบริสุทธิ์ครั้งเดียว |
| คำสั่ง | `set_automatic_self_calibration_enabled` (0x2416) | `perform_forced_recalibration` (0x362F) |
| ค่าเริ่มต้น | **เปิดอยู่** | — |

### ⚠️ ปัญหาของ ASC ในห้องแอร์

ห้องปรับอากาศที่ปิดตลอดมักไม่เคยลงถึง 400 ppm (มักอยู่ที่ 600–1,200 ppm)
ASC จะเข้าใจผิดว่าค่าต่ำสุดที่เจอ (เช่น 650 ppm) คือ 400 ppm แล้ว **ลบทุกค่าลง 250 ppm**

ผลคือค่า CO₂ ที่แสดง**ต่ำกว่าความจริงอย่างเป็นระบบ** และไม่มีสัญญาณเตือนใด ๆ

### เลือกแนวทาง

| สถานการณ์ | ทำอย่างไร |
|---|---|
| เปิดหน้าต่าง/ระบายอากาศจริงทุกสัปดาห์ | ✅ เปิด ASC ไว้ (ค่าเริ่มต้น) |
| **ห้องแอร์ปิดตลอด** | 🔴 **ปิด ASC** + ทำ FRC ทุก 6–12 เดือน |
| ไม่แน่ใจ | ปิด ASC + FRC (ปลอดภัยกว่า) |

### ขั้นตอนทำ FRC

> ⚠️ datasheet ระบุให้ทำ FRC **หลังประกอบเสร็จอย่างน้อย 5 วัน** ไม่ใช่ทันที
> เพราะสารระเหยจากบัดกรีและกาวยังรบกวนค่าอยู่

```
1. พาเซนเซอร์ไปที่อากาศบริสุทธิ์
   — นอกอาคาร ห่างจากถนน/คน/ต้นไม้หนาทึบ
   — ค่าอ้างอิงอากาศภายนอกทั่วไปคือ ~420 ppm (ตั้งเป็น config ไม่ hardcode)

2. เปิดเครื่องในโหมด periodic measurement ต่อเนื่อง ≥ 3 นาที
   (datasheet ระบุ 3 นาทีในสภาพแวดล้อมที่มี CO₂ สม่ำเสมอ)

3. stop_periodic_measurement()   →  รอ 500 ms

4. perform_forced_recalibration(420)
   ← เซนเซอร์จะตอบกลับค่า correction ที่ใช้
   ← ถ้าได้ 0xFFFF แปลว่า FRC ล้มเหลว (มักเพราะยังวัดไม่ครบ 3 นาที)

5. start_periodic_measurement()

6. ตรวจว่าค่าที่อ่านได้ใกล้ 420 ppm
```

**สิ่งที่ต้องระวัง:**

- ❌ **ห้ามหายใจใส่เซนเซอร์ระหว่างทำ FRC** — ลมหายใจมี CO₂ ~40,000 ppm
- ❌ อย่าทำในรถ ในลิฟต์ หรือใกล้กลุ่มคน
- ✅ ค่าอ้างอิง 420 ppm ต้องอยู่ใน config (`SCD40_FRC_TARGET_PPM=420`)
- ✅ ถ้าไม่มีทางออกไปข้างนอกได้ ให้เปิดหน้าต่างทิ้งไว้ 30 นาทีในห้องที่ไม่มีคน แล้วค่อยทำ

## SGP30 — baseline

**ขั้นตอนนี้โค้ดจัดการอัตโนมัติ** ไม่ต้องทำมือ แต่ต้องเขียนโค้ดให้ถูก

### วงจรการทำงาน

```
บูตระบบ
   ↓
Init_air_quality (0x2003)
   ↓
มีไฟล์ baseline.json ที่อายุ < 7 วันไหม?
   ├─ มี   → Set_baseline(tvoc, eco2)      ⚠️ สลับลำดับ! ไม่ใช่ (eco2, tvoc)
   └─ ไม่มี → ปล่อยเรียนรู้ใหม่ 12 ชั่วโมง
   ↓
ทิ้งค่า 15 วินาทีแรก (คืนค่าคงที่ 400/0)
   ↓
วนลูปอ่านทุก 1.000 วินาที ← ต้องเป๊ะ
   ↓
ทุก 1 ชั่วโมง (หลังผ่าน 12 ชั่วโมงแรกแล้ว):
   Get_baseline() → เขียน baseline.json แบบ atomic
```

### กฎที่ต้องยึด

| กฎ | เหตุผล |
|---|---|
| บันทึกทุก **1 ชั่วโมง** ไม่ใช่ทุกนาที | ถนอม SD card |
| baseline เก่ากว่า **7 วัน → ทิ้ง** | datasheet แนะนำ — ค่าเก่าเกินแย่กว่าไม่มีเลย |
| อย่าบันทึกก่อนครบ 12 ชั่วโมงแรก | จะบันทึก baseline ที่ยังไม่สมบูรณ์ |
| เขียนไฟล์แบบ atomic (temp file + rename) | กันไฟล์เสียตอนไฟดับ |
| `Set_baseline` รับ **(TVOC, eCO₂)** | แต่ `Get_baseline` คืน **(eCO₂, TVOC)** — สลับกัน! |
| path ของไฟล์อยู่ใน config | ไม่ hardcode |

### ⚠️ กับดักที่พบบ่อยที่สุด

**การสลับลำดับพารามิเตอร์ `Set_baseline`** — ไม่มี error ให้เห็น ค่ายังออกมาดูปกติ
แต่จะ drift ผิดทิศเรื่อย ๆ ตรวจจับได้ยากมาก **ตรวจโค้ดจุดนี้ให้ดี**

### เมื่อไหร่ควรลบ baseline ทิ้ง

- ย้ายเครื่องไปห้องอื่น
- ค่า TVOC ดูไม่สมเหตุสมผลติดต่อกันหลายวัน
- หลังเซนเซอร์สัมผัสสารเข้มข้น (สี ทินเนอร์ น้ำยาทำความสะอาด)

ลบไฟล์ `baseline.json` แล้วปล่อยให้เรียนรู้ใหม่ 12 ชั่วโมง

## ไมโครโฟน USB

### สิ่งที่ต้องเตรียม

- เครื่องวัด SPL หรือแอปวัดเสียงบนมือถือ (ความแม่นยำราว ±3 dB)
- แหล่งเสียงที่คงที่ — เพลง, white noise, หรือพัดลม

### ขั้นตอน

```
1. ติดตั้งไมค์ในตำแหน่งจริง

2. ตั้ง gain แล้วปิด AGC:
      amixer -c <card> sset 'Auto Gain Control' off
      amixer -c <card> sset 'Mic' 50%
   📝 จดค่า gain ไว้ในไฟล์ config — ต้องตั้งกลับทุกครั้งที่บูต

3. วางเครื่องอ้างอิงข้างไมค์ ห่างไม่เกิน 10 cm หันทิศเดียวกัน

4. เปิดเสียงคงที่ระดับปานกลาง (~60 dB)

5. อ่านค่าพร้อมกัน เฉลี่ย 30 วินาที:
      dB_อ้างอิง  = จากเครื่องวัด
      dB_คำนวณ    = 20 × log₁₀(RMS/32768)     ← ยังไม่ใส่ offset

6. OFFSET = dB_อ้างอิง − dB_คำนวณ

7. ตรวจซ้ำอีก 2 ระดับ (เงียบ ~40 dB · ดัง ~75 dB)
   ถ้า OFFSET ที่ได้ต่างกันเกิน 5 dB แสดงว่าไมค์ไม่เป็นเชิงเส้น
   → ใช้ค่าเฉลี่ยของทั้งสามจุด และยอมรับว่าความแม่นยำจำกัด

8. บันทึก OFFSET ลง config เช่น  MIC_DB_OFFSET=94.5
```

### 🔴 กฎเหล็ก

**หลัง calibrate เสร็จแล้ว ห้ามเปลี่ยนค่า gain อีกเด็ดขาด**
การเปลี่ยน gain ทำให้ OFFSET ใช้ไม่ได้ทันที และต้อง calibrate ใหม่ทั้งหมด

**วิธีป้องกัน:** ให้โปรแกรมตั้งค่า gain กลับเป็นค่าจาก config ทุกครั้งที่บูต

### ความแม่นยำที่คาดหวังตามจริง

**±5 dB** ในช่วงกลาง (40–85 dB) — เหมาะกับการดูแนวโน้ม ไม่เหมาะกับการอ้างอิงมาตรฐาน

## BH1750

จำเป็นเฉพาะเมื่อมีฝาครอบ/กระจกบังหน้าเซนเซอร์

```
1. วัด lux โดยไม่มีฝาครอบ ในแสงคงที่          → L_open
2. ใส่ฝาครอบ วัดซ้ำในแสงเดิมทันที             → L_covered
3. transmission = L_covered / L_open
4. บันทึกลง config: BH1750_TRANSMISSION_FACTOR=0.91
5. ในโค้ด: lux_จริง = lux_ที่อ่านได้ / transmission
```

**หรือถ้ามีเครื่องวัดแสงอ้างอิง:**

```
factor = lux_อ้างอิง / lux_ที่ BH1750 อ่านได้
```

ค่าทั่วไป: อะคริลิกใส 0.90–0.92 · กระจกใส 0.88–0.92 · อะคริลิกฝ้า 0.40–0.70

## MQ-2 (ถ้าใช้)

### ขั้นที่ 1 — Burn-in (ครั้งเดียวตอนซื้อมาใหม่)

จ่ายไฟต่อเนื่อง **24–48 ชั่วโมง** ค่าจะเปลี่ยนตลอด — เป็นเรื่องปกติ
**ห้าม calibrate ในช่วงนี้**

### ขั้นที่ 2 — หาค่า R0

```
1. วางในอากาศสะอาด (นอกอาคาร หรือห้องระบายอากาศดี ไม่มีควัน/กลิ่น)
2. เปิดทิ้งไว้ ≥ 20 นาที ให้ฮีตเตอร์เข้าที่
3. อ่าน Rs 100 ครั้ง (ห่างกัน 1 วินาที) แล้วหาค่าเฉลี่ย
4. R0 = Rs_เฉลี่ย / ratio_อากาศสะอาด        ← ratio ≈ 9.8 ตาม datasheet
5. บันทึกลง calibration/mq2_r0.json
```

**ค่า `ratio_อากาศสะอาด` ต้องอยู่ใน config** ไม่ใช่เขียน 9.8 ตรง ๆ ในโค้ด

### ขั้นที่ 3 — Warm-up ทุกครั้งที่บูต

รอ **3 นาที** ระหว่างนี้ส่ง `null` ไม่ใช่ส่งค่าที่อ่านได้

### calibrate ใหม่เมื่อ

ทุก 6 เดือน · หลังย้ายที่ · หลังไฟดับ > 24 ชม. · เมื่อค่าดูผิดปกติชัดเจน

## กล้อง — EAR threshold (ทางเลือก)

ค่าเริ่มต้น `WEBCAM.drowsyEarBelow = 0.18` ใน `config/sensors.js` ใช้ได้กับคนส่วนใหญ่
แต่ **EAR ต่างกันตามรูปตาของแต่ละคน** โดยเฉพาะคนที่มีตาชั้นเดียวหรือใส่แว่น

### วิธีปรับให้เข้ากับตัวเอง

```
1. รันโหมด debug ที่แสดงค่า EAR แบบเรียลไทม์
2. ลืมตาปกติ 30 วินาที       → จด EAR_เปิด   (ค่าเฉลี่ย)
3. หลับตา 10 วินาที           → จด EAR_ปิด    (ค่าเฉลี่ย)
4. threshold = (EAR_เปิด + EAR_ปิด) / 2
   หรือใช้  EAR_ปิด + 0.05  เพื่อให้ไวขึ้น
5. อัปเดตใน config/sensors.js → WEBCAM.drowsyEarBelow
```

**ค่าที่พบทั่วไป:** ตาเปิด 0.25–0.35 · ตาปิด 0.05–0.12 → threshold ~0.15–0.20

> ⚠️ ถ้าใส่แว่นตา แสงสะท้อนบนเลนส์อาจทำให้ landmark คลาดเคลื่อน
> ควรทดสอบทั้งแบบใส่และไม่ใส่แว่น แล้วเลือกค่าที่ทำงานได้ทั้งสองกรณี
